W4 PROJECT BRIEF

继续维护 W3 建立的 students/sXX/system/，不要另建第二个项目。本周只增加一个可选的诊断开关：让现有 market-check 在明确要求时，向 stderr 留下两处追踪。它帮助你观察程序走到了哪里，不改变 CSV 的检查规则。

旧命令必须继续可用：

  uv run --locked market-check <CSV 文件路径>

新增命令：

  uv run --locked market-check <CSV 文件路径> --trace

行为合同：

1. 不带 --trace 时，W3 的 stdout、stderr、退出状态与成功／失败行为均保持不变；不能默认打印追踪。
2. 带 --trace 时，在开始处理输入路径时向 stderr 打印第一条简短追踪；成功读入 CSV 后向 stderr 打印第二条简短追踪，并显示读入的行数。可用 print 与 f-string 实现。不要求统一追踪文案，但每条要能看出位置或对应的值。
3. 正常输入应有两条追踪，原有 stdout 和退出状态不变。文件不存在时，只能到达第一处追踪，仍明确失败。文件读入后发现缺少必要列时，两条追踪都应出现，仍明确失败。追踪出现不代表检查通过。
4. --trace 是无参数值的开关；与 CSV 路径的先后顺序不要求固定。不要向追踪写入 CSV 正文、环境变量或凭证。

先预测三种输入在 stderr 中分别留下几条追踪：正常 CSV、路径不存在、缺少 close 列。运行后再对照 stdout、stderr 与退出状态；至少解释一条公开测试为何能检验你的预测。教师测试只观察命令对外的行为，不规定包、模块或函数名。

从自己的 system/ 中运行累计公开测试：

  uv run --locked pytest -q ../../../course/week-03/tests ../../../course/week-04/tests
